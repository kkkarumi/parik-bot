# Бот онлайн-записи для барбершопов и салонов

Telegram-бот, через который клиенты записываются к мастеру сами, 24/7, без звонков.
Владелец салона настраивает всё прямо в боте командой `/admin`, программист ему не нужен.

## Что умеет

**Клиент**
- Запись в пару нажатий: услуга → мастер → день → время → телефон (одной кнопкой) → готово.
- Показываются только дни и часы, где реально есть окно. Двойная запись невозможна, это проверяется на уровне базы.
- Напоминания за 24 часа и за 2 часа с кнопками «Приду» и «Отменить».
- «Мои записи»: отмена с подтверждением. Мастер сразу получает уведомление.
- После визита бот просит поставить оценку. Отзыв приходит админу и мастеру.
- Прайс, контакты, ссылка на работы.
- Предоплата (если салон её включил): реквизиты, клиент присылает скрин чека, админ подтверждает. Если чека нет 30 минут, бронь снимается сама.

**Мастер** (подключается по ссылке-приглашению, админ получает «мастер подключился»)
- Свой кабинет в боте: записи, выходные, график.
- Уведомления о новых записях (в том числе ждущих предоплату), отменах и отзывах.
- Сам отмечает выходной или отгул: клиенты на этот день не запишутся, админ получит уведомление.
- `/schedule`: все свои предстоящие записи и расписание по дням. Из карточки записи можно отменить запись (клиент получит уведомление) или отметить «не пришёл».
- Карточка клиента: история визитов, неявки, сумма, заметки («любит покороче»).

**Админ** (`/admin`)
- **Записи клиентов**: все предстоящие записи списком, фильтр по мастеру, отмена с уведомлением клиента.
- Услуги и цены: добавить, изменить цену или длительность, скрыть.
- Мастера: добавить, график по дням недели (можно с перерывом), выходные на даты, какие услуги делает, приглашение в бот.
- Данные салона: название, адрес, телефон, часы, ссылка на работы, приветствие.
- Предоплата: сумма и реквизиты, подтверждение чеков одной кнопкой.
- Статистика за 7, 30 или 90 дней: выручка, визиты, отмены, неявки, новые клиенты, рейтинг, топ мастеров и услуг.
- Поиск клиента по имени или телефону, блокировка злостных «непришедших».
- Рассылка всем клиентам (акции, свободные окна) с превью перед отправкой.
- Ссылка на бота и **QR-код** для печати на стойку.
- Передача админки владельцу по одноразовой ссылке.

## Как устроено

```
bot/       Telegram-бот (python-telegram-bot 22). Только интерфейс, данных не хранит
backend/   API (FastAPI) + база (PostgreSQL / SQLite) + фоновые задачи: напоминания, отзывы, снятие неоплаченных броней
e2e/       сквозные тесты: настоящий бот + настоящий API, Telegram подменён
```
Бот ходит в API по секретному ключу (`TENANT_API_KEY`). Напоминания шлёт сам бэкенд, поэтому перезапуск бота ничего не ломает. Схема базы обновляется сама при старте (Alembic).

## Установка для салона (VPS, ~10 минут)

Нужен сервер с Linux (Ubuntu 22/24) и 1 ГБ памяти, плюс токен бота от [@BotFather](https://t.me/BotFather).

```bash
curl -fsSL https://get.docker.com | sh            # если Docker ещё не стоит
git clone https://github.com/kkkarumi/parik-bot.git salon-parik
cd salon-parik
./setup.sh
```

`setup.sh` спросит токен и название салона, сгенерирует пароли, запустит всё в Docker и выдаст **ссылку для админа**. Откройте её в Telegram, и вы администратор. Дальше:

1. `/admin` → **Услуги и цены**, **Мастера** (график, выходные), **Салон** (адрес, телефон).
2. `/admin` → **Мастера** → мастер → «Подключить к боту». Перешлите ссылку мастеру.
3. `/admin` → **Салон** → «Передать админку». Отдайте ссылку владельцу салона.
4. `/admin` → **Ссылка и QR-код**: ссылку в Instagram и на карты, QR распечатать.

Чтобы показать салону «как будет выглядеть», на шаге `setup.sh` ответьте `y` на демо-данные: появятся 4 услуги и 2 мастера.

**Несколько салонов на одном сервере.** Для каждого салона своя копия папки (`git clone … salon-имя`) и свой `./setup.sh`. Docker разводит их по имени папки, базы не пересекаются. На 2 ГБ памяти спокойно живут 4–5 салонов.

## Обслуживание

| Что | Команда |
|---|---|
| Обновить до новой версии (с бэкапом) | `./scripts/update.sh` |
| Бэкап базы | `./scripts/backup.sh` → `backups/*.sql.gz` (хранятся 14 последних) |
| Ежедневный бэкап | `crontab -e` → `15 4 * * * cd /root/salon-parik && ./scripts/backup.sh >> backups/backup.log 2>&1` |
| Восстановить | `gunzip -c backups/ФАЙЛ.sql.gz \| docker compose exec -T db psql -U app -d app` |
| Логи | `docker compose logs -f --tail 100 bot backend` |
| Что в базе | `docker compose exec backend python -m app.manage status` |
| Новая ссылка для админа | `docker compose exec backend python -m app.manage admin-link` |
| Перезапуск | `docker compose restart` |

Настройки в `.env` (см. `.env.example`): шаг сетки времени, горизонт записи, лимит активных записей на клиента, время ожидания чека.

## Локальный запуск (Mac/Linux, без Docker)

```bash
cp .env.example .env     # вписать BOT_TOKEN, TENANT_API_KEY (любая длинная строка), SALON_NAME
./run_local.sh
```
Скрипт сам создаст `.venv`, поставит зависимости, поднимет API на SQLite (`backend/parik.db`) и запустит бота. Остановить: `Ctrl+C`. Демо-данные: `cd backend && ../.venv/bin/python -m app.manage demo`.

Один токен — один запущенный бот. Если этот же бот уже работает где-то ещё, Telegram выдаст ошибку `Conflict`. Остановите другой экземпляр.

## Разработка

```bash
pip install -r requirements-dev.txt
```

Тесты:

```bash
cd backend && pytest        # API: запись, конфликты, напоминания, предоплата, роли, миграции
cd .. && pytest             # e2e: бот + API, все сценарии клиента, мастера и админа
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost/db pytest   # то же на Postgres
```
