# Релей Telegram Bot API

**Зачем.** С российских VPS соединение с `api.telegram.org` часто не устанавливается: DNS и ping проходят, а TCP:443 висит. Бот и бэкенд остаются на сервере в РФ (там же база с данными клиентов), а все запросы к Telegram идут через этот релей — маленький VPS за границей с [Caddy](https://caddyserver.com), который просто пересылает запросы в `api.telegram.org`.

```
сервер в РФ (бот + бэкенд + БД) ──HTTPS──▶ релей за границей (Caddy) ──HTTPS──▶ api.telegram.org
         TELEGRAM_API_BASE=https://ДОМЕН/СЕКРЕТ
```

Бот работает на long polling: все соединения исходящие, на сервер в РФ снаружи никто не ходит, webhook не нужен.

**Один релей обслуживает сколько угодно салонов.** Токен бота идёт в каждом запросе (`/СЕКРЕТ/bot<TOKEN>/…`), поэтому у всех ботов один и тот же `TELEGRAM_API_BASE`. Нагрузка копеечная: текстовые сообщения и один «висящий» запрос getUpdates на бота.

## Что нужно

- VPS за границей (Турция, Казахстан, Европа…): Ubuntu 22.04/24.04, 1 vCPU, 512 МБ памяти хватит. ⚠️ Проверьте до покупки, что с вашего российского сервера до этого хостинга вообще есть связь (`curl -m 10 https://IP-или-сайт-хостинга`).
- **Домен или поддомен**, A-запись которого указывает на IP релея. Без домена Caddy не получит обычный сертификат (см. «Если домена нет»).
- Открытые входящие порты **80** и **443** на релее (80 нужен Let's Encrypt для выпуска сертификата).

## Установка (≈10 минут)

1. **DNS.** В панели домена создайте A-запись, например `tg-relay.example.com → IP релея`. Проверьте с любого компьютера (обновление DNS может занять до часа):
   ```bash
   getent hosts tg-relay.example.com
   ```
2. **Зайдите на релей по SSH и поставьте Docker:**
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **Скопируйте папку `relay/`** (нужны три файла: `Caddyfile`, `docker-compose.yml`, `.env.example`):
   ```bash
   git clone https://github.com/kkkarumi/parik-bot.git
   cd parik-bot/relay
   ```
   (или `scp -r relay root@IP-релея:/root/relay` со своего компьютера)
4. **Настройки:**
   ```bash
   cp .env.example .env
   sed -i "s/^RELAY_SECRET=.*/RELAY_SECRET=$(openssl rand -hex 16)/" .env
   nano .env          # впишите RELAY_DOMAIN=tg-relay.example.com
   chmod 600 .env
   cat .env           # запишите секрет — он понадобится на серверах с ботами
   ```
5. **Если включён файрвол** (`ufw status` показывает active):
   ```bash
   ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp
   ```
6. **Запуск:**
   ```bash
   docker compose up -d
   docker compose logs -f     # ждём строку "certificate obtained successfully", выход — Ctrl+C
   ```
7. **Проверка** (с любого компьютера, подставьте свои домен, секрет и токен бота):
   ```bash
   curl -s https://tg-relay.example.com/СЕКРЕТ/bot<TOKEN>/getMe
   # ждём: {"ok":true,"result":{"id":…,"is_bot":true,…,"username":"…"}}
   curl -s -o /dev/null -w '%{http_code}\n' https://tg-relay.example.com/
   # ждём: 404 (без секрета релей «пустой»)
   ```
8. **Проверка с российского сервера** — то же `curl … /getMe`, но выполнить на VPS в РФ. Если там ответ есть, а `curl -m 10 https://api.telegram.org` висит — релей делает своё дело.
9. **Подключить салон.** На сервере с ботом в `.env` салона:
   ```bash
   TELEGRAM_API_BASE=https://tg-relay.example.com/СЕКРЕТ
   ```
   затем
   ```bash
   docker compose up -d
   docker compose exec backend python -m app.manage check-telegram
   # ждём: OK, бот @имя_бота (Telegram через https://tg-relay.example.com/…)
   ```
   Так для каждой папки-салона на сервере.

## Защита от «открытого релея»

Без защиты любой мог бы гонять через ваш сервер свои боты. Включено по умолчанию:

1. **Секретный префикс пути.** Запросы без `/RELAY_SECRET/` в начале получают 404. Секрет — 32 случайных символа, перебрать нереально. Он хранится в `.env` релея и в `TELEGRAM_API_BASE` салонов.
2. **(дополнительно) Ограничение по IP.** Если IP серверов с ботами постоянные, впишите их в `RELAY_ALLOW_IPS` через пробел и перезапустите:
   ```bash
   # relay/.env
   RELAY_ALLOW_IPS=203.0.113.10 198.51.100.7
   ```
   ```bash
   docker compose up -d
   ```
   С остальных IP — 404 даже с правильным секретом. IP своего сервера в РФ смотрите в панели хостинга.
   ⚠️ Проверьте после включения, что `check-telegram` на серверах с ботами по-прежнему `OK`. Если в журнале релея у всех запросов IP вида `172.x.x.x` (Docker подменил адрес), ограничение по IP в такой конфигурации не сработает — тогда оставьте только секрет.

## Токены в логах

В пути запроса есть секрет релея и токен бота, поэтому в `Caddyfile` путь (`request>uri`) и заголовки вырезаются из журнала запросов и из служебных логов Caddy. В `docker compose logs` видно время, IP, статус и длительность — этого хватает, чтобы понять, ходят ли боты через релей. Логи Docker ограничены 3 файлами по 10 МБ.

## Сменить секрет

Например, если `.env` салона куда-то утёк.

1. На релее: новый секрет в `relay/.env` и перезапуск.
   ```bash
   sed -i "s/^RELAY_SECRET=.*/RELAY_SECRET=$(openssl rand -hex 16)/" .env && grep RELAY_SECRET .env
   docker compose up -d
   ```
2. Сразу на каждом сервере с ботами: новый секрет в `TELEGRAM_API_BASE` и `docker compose up -d`.

Пока секрет не обновлён на сервере бота, бот не получает сообщения (повторяет попытки сам), а бэкенд копит неотправленные напоминания и дошлёт их, когда связь вернётся. Делайте оба шага подряд, за пару минут.

## Если домена нет

- **Обычный путь — купить домен** (самый дешёвый в любой зоне) или взять поддомен у знакомого и направить A-запись на релей.
- **Бесплатные поддомены**: сервисы вида `IP.sslip.io` / `nip.io` (имя `203-0-113-10.sslip.io` указывает на `203.0.113.10`) или DuckDNS. Caddy может получить на такое имя сертификат Let's Encrypt. ⚠️ проверить: что сервис жив и доступен из РФ, и что общий лимит Let's Encrypt на такие домены не исчерпан (сертификат может не выдаться).
- **Сертификат на голый IP.** Let's Encrypt с 2026 года выдаёт короткие (≈6 дней) сертификаты на IP-адреса. ⚠️ проверить: поддерживает ли это ваша версия Caddy и как это включить; это не настроено в этом `Caddyfile`.
- **Просто HTTP без сертификата — нельзя.** Токен бота и сообщения клиентов (имена, телефоны) пойдут через границу открытым текстом, их увидит любой посредник, включая ТСПУ.

## Что важно знать

- Релей расшифровывает трафик (так работает любой HTTPS-прокси): через него проходят токены ботов и тексты уведомлений, где есть имена и телефоны клиентов. Это **ваш** сервер, держите его в порядке: обновления (`apt upgrade`), вход по SSH-ключу, `.env` с правами 600. Для юриста это трансграничная передача данных — см. `docs/legal/поручение_обработки_пдн.md`.
- Релей может стать недоступен (блокировка, проблемы хостинга). Бот при этом не падает, а повторяет попытки; напоминания досылаются, пока не потеряли смысл. Держите в голове запасной вариант: второй VPS у другого хостинга с тем же `Caddyfile`. Переключение — смена `TELEGRAM_API_BASE` и `docker compose up -d`.
- Обновить Caddy: `docker compose pull && docker compose up -d`.
